# 技术实现说明

这份文档写给想读懂或修改代码的人：页面是怎么搭起来的，每一帧发生了什么，各个物理效果在代码里怎么实现，以及怎样加一个新地点、新生物或新的讲解。

## 1. 总体结构

```
index.html            页面结构与全部界面文字（控制台、弹窗、玩法说明、页面内更新记录）
css/style.css         样式
src/NN-*.js           程序源码，按功能分成 38 个文件
js/seafloor.js        由 src/ 拼接生成，页面实际加载的脚本（不要手改）
data/etopo20.js       全球地形数据，打开地图时才加载
narration/tour.json   展览模式讲解词
audio/tour/           MiniMax 生成的讲解音频与 manifest.json
assets/               分享预览图、网站图标
tools/                构建、检查、配音生成、文档同步脚本
docs/                 项目文档
```

技术选型：

- **three.js r128**，从 CDN 加载；后期处理用它的 `EffectComposer`、`UnrealBloomPass`、`ShaderPass` 示例模块。
- **不使用打包工具和框架**。网站是纯静态文件，GitHub Pages 直接托管。
- **工具脚本只用 Python 标准库**（另有 `node --check` 做语法检查），在任何装了 Python 3 的电脑上都能运行。

### 为什么源码是“分段拼接”的

整个程序是**一个闭包**：`src/00-bootstrap.js` 以 `(function(){` 开头，`src/99-main-loop.js` 以 `})();` 结尾，中间各文件按文件名顺序拼起来，共享同一个作用域。这样做的原因：

- 程序最初是单文件写成的，各系统之间直接共享状态（比如水体光学参数 `U`、全局状态 `S`、潜水状态 `DIVE`）。拆分时我们按原有的章节切开，构建后与拆分前的文件**逐字节相同**，确保拆分本身不改变任何行为。
- 不需要打包器，也不需要处理模块导入导出。

代价是：单个 `src/` 文件不是独立可运行的 JavaScript，顺序也有讲究。一个文件在**加载时立刻执行**的代码，只能用前面文件里已经声明的东西；写在函数里、运行时才调用的代码不受这个限制。编号决定顺序，所以新文件要选一个合适的编号插进去。

## 3. 状态与数据流

几个全局对象贯穿各模块：

| 对象 | 作用 |
| --- | --- |
| `S` | 当前环境：水深 `D`、水质、水温、波高 `H` 与周期 `T`、海流、太阳高度、昼夜、手电、当前地点 `loc` |
| `U` | 所有水下材质共享的着色器 uniform（衰减系数、相机位置、时间、手电、焦散强度等），改一处全场生效 |
| `OPT` | 由水质和太阳高度算出的漫射衰减系数 `K` 与光束衰减系数 `c` |
| `H` | 生境开关，例如 `H.coral`、`H.kelp`，决定哪些生物出现 |
| `DIVE` / `PILOT` / `TOUR` / `VR` | 下潜、驾驶、导览、VR 各模式的状态 |
| `FISH` / `JELLY` / `DRIFT` | 各类动物群，每种一个 InstancedMesh |

改变环境的路径是固定的：

```
applyLocation(id)            选地点：写入 S，摆好相机
  └─ applyDepth(D)           改水深
       └─ rebuild()          重算光学 → 判定生境 H → 生成或隐藏各类生物和地形
            └─ zoneUpdate()  按深度和水温启用对应的鱼群、水母、漂浮生物
```

`rebuild()` 只在环境参数改变时运行；每帧只做动画和模拟。

## 4. 水下光学（03-water-optics.js、31-habitat-rebuild.js）

### 4.1 衰减系数

每种水质给出红、绿、蓝三个波段的吸收系数 `a` 和散射系数 `b`（`WATER` 表）。`updateOptics()` 由此计算：

- 光束衰减系数 `c = a + b`：决定能看多远、远处物体多快融进水色。
- 漫射衰减系数 `K = √(a² + 0.256·a·b) / μ₀`（Kirk 1984 的近似）：决定阳光随深度减弱多快。μ₀ 是水中折射后太阳方向的余弦，太阳折射角按斯涅尔定律算，水的折射率取 1.34。
- 背景水色 `0.6·b/(a+b)`：散射占比越高，水越亮。

红光吸收最强，所以 `K` 和 `c` 的红色分量最大，这就是十几米以下一切变蓝绿的原因，不需要手工调色。

### 4.2 着色器补丁 `waterify()`

页面里几乎所有物体都用 three.js 自带的 Lambert 材质，再用 `waterify(mat, key, opts)` 在编译前改写它的着色器（`onBeforeCompile`）。补进去的计算是：

```
颜色 = 物体颜色 × E(深度) × T + 水色背景 × (1 − T) + 手电照明 + 自发光
E(z) = exp(−K·z)            阳光到达这个深度后剩下的部分
T    = exp(−c·距离)          从物体到眼睛这段水的透过率
```

在此基础上还可以按需打开几项效果（用 `defines` 开关）：焦散（程序生成的光纹，随深度减弱）、沙纹、荧光（蓝光手电加黄色滤镜时的荧光蛋白）。手电是一个跟着相机朝向的锥形光，同样按 `c` 衰减。

北极浮冰边缘用 uniform `uIce` 把冰缘也写进这个公式：冰缘是一条曲线 `x = iceEdge(z)`（JS 里同一个函数叫 `arcEdge`），冰下的物体再乘一个系数 `iceSh`——冰下只剩约 3% 的光，越靠近冰缘、越往深处，从开阔水侧向漫进来的光越多；背景水色也按视线朝冰下还是朝开阔水调暗或调亮。气泡、相机、自由驾驶的上限和光柱位置都用同一条冰缘曲线判断。

每个补丁材质有自己的 `customProgramCacheKey`，避免 three.js 把不同补丁的着色器混用。另外 `cameraPosition` 被重定义为 `uCamPos`，因为 VR 立体渲染时左右眼要共用同一个水体视点。

### 4.3 曝光与白平衡

主循环每帧估算眼前的光量，用 `目标曝光 ∝ 光量^(−0.5)` 慢慢逼近，模拟人眼适应；深海和夜间有上限，避免把黑暗硬拉亮。后期处理的最后一步做白平衡（按当前深度剩余的光谱补偿）、暗角和手电造成的水中光晕。深海白光手电只对灯照到的部分做白平衡，水本身保持深蓝，模仿潜水器相机。

### 4.4 后期处理链

渲染（半浮点精度缓冲）→ 泛光（让生物发光有光晕）→ 白平衡、暗角与光晕。色调映射用 ACES，输出 sRGB。

## 5. 波浪、海流与生境

- **波浪**：`solveWave()` 迭代求解线性波浪色散关系 `ω² = g·k·tanh(k·h)`，`orbital()` 给出任意深度的水质点轨道速度；巨藻、海扇、气泡、漂浮颗粒和驾驶的潜水器都受它推动。
- **海流**：对数剖面，海底粗糙度 z₀ = 0.003 m。
- **沙纹**：比较海底的波浪轨道速度和海流速度，决定生成波浪沙纹还是海流沙纹；波浪沙纹的波长按轨道位移估算。
- **生境判定**：`rebuild()` 根据水温、剩余光量、水深、海流等算出 `H` 的每一项。例如造礁珊瑚需要水温 ≥ 18 °C、剩余光 ≥ 1%、水深 ≤ 150 m；巨藻需要 3–20 °C 和 35 m 以浅。所以在“环境参数”里随便改条件，出现的生物也会跟着合理变化。

## 6. 生物

- **鱼群**：每个物种一个 `InstancedMesh`，用 Boids 规则（对齐、聚拢、分离）模拟。还有几种附加行为：
  - 待在活动范围内，或围着礁石“家”打转；
  - 绕圈游（`mill`）；
  - 迎着海流游（趋流性）；
  - 避开海底和水面；
  - 被波浪轨道速度带着漂。
- **水母**：自定义半透明着色器，伞部按节律收缩；冠水母被点击时会触发“防盗警报”式的闪光。
- **按深度出现**：`ZR` 表和 `zoneUpdate()` 按深度和水温启用对应物种；下潜时鱼群会跟着潜水器重新定位。
- **几何体合并**：大量静态物体（珊瑚、岩石）用 `Acc / addGeo / finishGeo` 合并成少数几个网格，减少绘制调用。
- **放样造型**（`07-megafauna.js`）：`loftGeo(nA, nB, fn)` 沿身体方向 a 和绕身体一圈 b 生成光滑曲面，`fn(a,b)` 同时返回顶点位置和颜色，法线自动朝外。花纹用细胞噪声 `cell2 / cell3`（到最近和次近随机点的距离）生成：海龟的盾片缝、鳞片的浅色边、鲸鲨的斑点都是这样算出来的。绿海龟、蝠鲼、鲸鲨用的就是这套工具。

## 7. 特殊地点模块的写法（20–28 site-*）

每个特殊地点都按同一个套路写：

1. 一个状态对象，例如 `BR`（盐池）、`ICE`、`TRUK`；
2. `buildXxx(on)`：第一次需要时生成几何体，之后只切换显示，由 `rebuild()` 调用；
3. `stepXxx(dt, t)`：每帧动画，由主循环调用；
4. 可点击的部件用 `regPick(mesh, key)` 注册，信息卡内容写在 `CHIM_INFO`；
5. 在 `LOC` 加地点参数，在 `SITE` 加介绍和“看点”，在 `frameCamera()` 加相机机位，需要时在 `applyLocation()` 加进入和离开的处理。

## 8. 每一帧（99-main-loop.js）

```
frame(now)
  ├─ 计算真实时间步长 rdt 和模拟步长 dt（上限 1/25 s，防止卡顿时模拟失控）
  ├─ 模式推进：下潜、导览、VR、驾驶，否则相机环绕
  ├─ 任务、触碰发光
  ├─ 相机限制在海底以上、水面（或冰底）以下
  ├─ 更新共享 uniform：时间、相机深度与位置、海流方向
  ├─ 模拟：巨藻、鱼群、水母、蝠鲼与海龟、漂浮生物、大型生物、声音、各特殊地点
  ├─ 图鉴“遇见”判定（每 0.5 秒一次）、提示消息
  ├─ 粒子：气泡、海洋雪、闪光、光柱
  ├─ 曝光与白平衡
  └─ 渲染：头显 VR 直接渲染；分屏 VR 左右眼各走一遍后期处理；否则正常走后期处理
```

## 9. 各项功能的实现要点

| 功能 | 实现 |
| --- | --- |
| 下潜到海沟 | 相机和目标点一起下移，`setDiveZ()` 跨过 `MILESTONES` 的深度时弹出字幕；左侧剖面图是按比例画的 SVG |
| 昼夜垂直迁移 | 动物追随固定亮度的等光面上下移动，限制游速；回声测深图画在 canvas 上 |
| 海底盐池 | 卤水与海水界面上的内波：约化重力 g′ ≈ 0.30 m/s²，色散关系 ω² = g′k；湖面反射用菲涅尔公式（相对折射率 1.0127） |
| 触碰发光 | 按水流剪切应力判断：τ = μU/δ，边界层厚度 δ = 5√(νL/U)，超过约 0.15 Pa 才发光 |
| 自由驾驶 | 推力约 0.9 m/s²、二次阻力、海流与波浪漂移、60 m 缆绳 |
| 深海声道 | Mackenzie (1981) 声速公式，按射线不变量 cosθ/c 追踪 25 条声线；“听”的功能用 Web Audio 合成 1,000 km 外的到达信号 |
| 压力实验 | 静水压强；泡沫杯按泡孔被压塌的模型缩小，水的压缩率 4.6×10⁻¹⁰ /Pa |
| 全球地形图 | ETOPO 20 角分数据，8 位量化（h = q/255 × 15400 − 9100 m），双线性插值；地形晕渲画在 canvas 上 |
| 图鉴 | `CAT` 条目加 `isSeen()` 判定；遇见过的存在浏览器 `localStorage`（键名 `seafloor-found`） |
| 共享图鉴 | 只在 Claude 版本里有：通过 Claude 的共享存储，每人写自己那一份，所有人读汇总 |
| 明信片 | 重新渲染一帧，排版成 1600×1000 的 canvas，再导出图片 |
| VR | 分屏：three.js `StereoCamera`，眼距 64 mm，左右半屏各走一遍后期处理；头显：WebXR，把相机挂在一个“推车”上，摇杆移动的是推车 |
| 展览模式 | `TOUR_STOPS` 列出各站；下潜那一站按深度关键帧推进，保证每句讲解讲完再到下一个深度 |
| 本地存储 | `seafloor-found`（图鉴）、`seafloor-missions`（任务）、`seafloor-welcome`（是否看过欢迎卡） |

## 10. 语音讲解

```
narration/tour.json ──(GitHub Actions：生成导览配音)──▶ tools/gen_tts.py ──▶ MiniMax 语音合成接口
                                                              │
                                                              ▼
                                         audio/tour/*.mp3 + manifest.json（提交回仓库）
                                                              │
网页（49-tour-narration.js）◀───────── 读取 manifest，用 Web Audio 播放
```

- **生成**：讲解词里的数字和单位写成汉字读法，避免合成时读错。`gen_tts.py` 对每句话的文本、音色、模型和语速算一个签名，只重新生成签名变了的句子。密钥存在 GitHub 仓库的 Secrets 里，不进代码，也不进网页。
- **播放**：点击“展览模式”的那一下创建并解锁 `AudioContext`，之后换站时由计时器直接开始播放，不受手机自动播放限制。下一站的音频会提前下载解码。每站停留时间取 `max(设定时长, 音频时长 + 4 秒)`。音频不可用时导览只显示字幕。

## 11. 性能

- **像素比**：上限 1.75，高分屏手机不会按 3 倍分辨率渲染。
- **绘制调用**：同种动物用 InstancedMesh，静态物体合并网格。
- **按需生成**：特殊地点的几何体第一次进入时才生成，之后只切换显示。
- **按需加载**：0.8 MB 的地形数据只在打开地图时加载。首屏需要下载的是页面、样式和约 300 KB 的脚本，加上 three.js。
- **固定模拟步长**：卡顿时模拟步长不超过 1/25 秒，避免动物瞬移或穿墙。
- **版本标记**：`index.html` 里的样式和脚本地址带 `?v=内容哈希`。内容一变，浏览器就会取新文件；内容不变就继续用缓存。

  - “检查”工作流：确认生成的脚本与源码一致、语法正确、版本标记最新、讲解词和音频对得上、文档与页面同步；
  - Pages 发布：一两分钟后网站更新。
- **改了讲解词**：会自动触发“生成导览配音”工作流。

## 13. 常见改动怎么做

**加一个新地点**

1. 在 `src/01-constants-sites-state.js` 的 `LOC` 里加参数（深度、水质、水温、波浪、海流、太阳高度、手电）。
2. 如果地点有专属的地形或生物，新建 `src/2x-site-xxx.js`，按第 7 节的套路写 `build` 和 `step`，并在 `rebuild()` 和主循环里调用它们。
3. 在 `src/32-ui.js` 的 `SITE` 里写介绍和看点，在 `frameCamera()` 里定机位。
4. 在 `index.html` 的地点按钮里加一个按钮，在页面内更新记录里登记，并补充资料来源。
5. 如果要加进展览导览，在 `TOUR_STOPS` 里加一站，并在 `narration/tour.json` 里加同名 id 的讲解词。

**加一种生物**

1. 做几何体，决定它属于哪一类：鱼群用 `FISH`、漂浮生物用 `DRIFT`、水母用 `JELLY`，固着生物放进 `05-benthos.js`。
2. 在 `CAT` 里加图鉴条目（键名、中文名、学名、分布深度），在 `isSeen()` 里写“遇见”的条件，在 `FACTS` 里写信息卡上的一句话。
3. 用 `regPick()` 注册，让它可以被点击识别。

**改讲解词**

编辑 `narration/tour.json` 并提交，配音会自动重新生成；不要改 `id`，否则网页对不上。换音色或语速：在仓库 Settings → Secrets and variables → Actions → Variables 里设置 `MINIMAX_VOICE_ID`、`MINIMAX_SPEED`，再手动运行一次“生成导览配音”。
